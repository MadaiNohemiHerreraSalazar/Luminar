# UC-05 — Gerar Trajeto com Smart Routing (Prioridade de Segurança)

**Produto:** Luminar  
**Objetivo:** Calcular e apresentar o trajeto ideal entre dois pontos, priorizando vias que possuam melhores índices de iluminação, presença de comércios ativos e fluxo de pessoas, garantindo uma rota preventiva.

## Atores

- **Usuária**
- **Sistema (Algoritmo Luminar / PostGIS / Mapbox API)**

## Regras de Negócio Aplicadas

### RN-01 — Ponderação do Índice de Segurança (Score)
- O algoritmo deve atribuir pesos de 0.0 a 1.0 para cada segmento de via (edge) baseado em:
    - **Peso 0.4:** Iluminação pública (dados da prefeitura + relatos de "luz quebrada").
    - **Peso 0.3:** Estabelecimentos abertos (Google Places API / Base interna de Pontos Violeta).
    - **Peso 0.3:** Movimentação e relatos colaborativos de "rua movimentada" vs "rua deserta".

### RN-02 — Penalização de Áreas Críticas
- Vias com relatos recentes (últimas 12h) de assédio ou perigo iminente devem receber uma penalização severa no custo do grafo, sendo evitadas pelo algoritmo a menos que não haja outra alternativa possível.

### RN-03 — Tolerância de Tempo (Efficiency Gap)
- O trajeto "Smart" não deve exceder em mais de 20% o tempo estimado da rota mais rápida, buscando o equilíbrio entre chegar ao destino e permanecer em segurança.

### RN-04 — Atualização Horária
- O Smart Routing deve recalcular a rota se o horário da consulta mudar o status dos comércios (ex: uma rota segura às 18h pode não ser a mesma às 23h devido ao fechamento de lojas).

## Caso de Uso: UC-05

### Pré-condições

- Conexão de dados ativa.
- Acesso ao banco de dados geoespacial para consulta de infraestrutura.
- Origem e destino definidos pela usuária.

### Gatilho

- A usuária insere um destino e seleciona a opção **"Buscar Rota Segura"**.

### Fluxo Principal (Sucesso)

1. O sistema envia as coordenadas de origem e destino para o backend.
2. O sistema consulta a malha viária e extrai os metadatos de segurança de cada trecho.
3. O algoritmo **Smart Routing** processa o grafo de caminhos, aplicando os pesos de iluminação e movimento (RN-01).
4. O sistema gera a linha da rota priorizando as "vias verdes" (alto score de segurança).
5. O sistema identifica pontos de apoio (Pontos Violeta) ao longo do trajeto gerado.
6. O sistema exibe o trajeto no mapa com uma cor diferenciada (Verde Luminar).
7. O sistema apresenta um resumo: "Rota 12% mais longa, porém 85% mais iluminada".
8. A usuária confirma e inicia o deslocamento.

### Pós-condições

- A rota segura é fixada na tela de navegação.
- O sistema monitora se a usuária permanece no trajeto sugerido.

## Cenários de Validação

### CT-01 — Priorização de Avenida em vez de Atalho
**Dado** que o caminho mais curto é por um beco residencial sem saída e escuro  
**Quando** a usuária solicita a rota  
**Então** o sistema deve sugerir o contorno por uma avenida principal iluminada, mesmo que adicione 200 metros ao trajeto.

### CT-02 — Ajuste de Rota por Horário (Fechamento de Comércio)
**Dado** uma rua com muitas lojas que fecham às 22h  
**Quando** a consulta é feita às 23h  
**Então** o Smart Routing deve diminuir o score dessa rua e sugerir uma via alternativa que possua estabelecimentos 24h.

### CT-03 — Desvio de "Zonas Desertas"
**Dado** uma via com múltiplos relatos de "Rua Deserta" nas últimas horas  
**Quando** o algoritmo processa o caminho  
**Então** o custo dessa via deve ser elevado para que o trajeto seja traçado por ruas com maior fluxo de pedestres.

### CT-04 — Rota sem alternativa segura
**Dado** uma região onde todas as vias possuem baixo índice de segurança  
**Quando** a usuária solicita a rota  
**Então** o sistema deve sugerir a "menos insegura" e emitir um alerta visual: "Atenção: Área com baixa infraestrutura reportada".

### CT-05 — Exibição de Justificativa da Rota
**Dado** que a rota segura foi gerada  
**Quando** a usuária visualiza os detalhes do trajeto  
**Então** o sistema deve listar os benefícios (ex: "Passa por 3 Delegacias e 5 Comércios abertos").
