# UC-09 — Atualizar Banco de Dados Geográfico (Feedback Loop)

**Produto:** Luminar  
**Objetivo:** Processar os dados de avaliação recebidos das usuárias, aplicar algoritmos de ponderação e atualizar as tabelas geoespaciais (PostGIS) para refletir o estado atual de segurança das vias.

## Atores

- **Sistema (Serviço de Processamento de Dados / Backend)**
- **Banco de Dados (PostGIS)**

## Regras de Negócio Aplicadas

### RN-01 — Cálculo do Índice de Solidariedade (Score Dinâmico)
- O score de uma via deve ser recalculado a cada novo feedback, utilizando uma média ponderada que considera:
    - **Média Histórica (40%):** Dados consolidados de infraestrutura.
    - **Feedback Recente (60%):** Avaliações das últimas 48 horas (prioridade para o "agora").

### RN-02 — Filtro de Relevância Temporal
- Relatos sobre "Comércio Aberto" ou "Movimentação" devem impactar apenas a faixa horária em que foram gerados (ex: um feedback das 22h não deve melhorar o score da rua para as 10h da manhã).

### RN-03 — Higienização de Dados (Anti-Spam)
- Caso uma via receba múltiplos feedbacks divergentes (ex: várias notas 5 e uma nota 1 repentina) em um curto espaço de tempo, o sistema deve marcar o dado como "Pendente de Validação" e não alterar o mapa imediatamente.

### RN-04 — Persistência Geoespacial
- O sistema deve vincular o feedback ao ID específico do segmento de rua (OSM ID) no banco de dados para garantir que a mudança visual ocorra exatamente no trecho percorrido.

## Caso de Uso: UC-10

### Pré-condições

- O UC-09 (Avaliação Pós-Trajeto) foi concluído com sucesso e os dados foram recebidos pelo servidor.
- O serviço de geprocessamento está operacional.

### Gatilho

- Recebimento de um novo pacote de dados de avaliação (JSON) via API.

### Fluxo Principal (Sucesso)

1. O sistema recebe o pacote de dados contendo: Notas, Tags, Timestamp e Coordenadas da Rota.
2. O sistema identifica os segmentos de via (edges) que compunham a rota percorrida.
3. Para cada segmento, o sistema aplica a fórmula do **Índice de Solidariedade**, cruzando a nota da usuária com o histórico existente.
4. O sistema verifica se há conflitos de dados (RN-03).
5. O sistema atualiza os atributos de segurança na tabela de vias do **PostGIS**.
6. O sistema dispara uma atualização para o cache do mapa (Mapbox Tilesets) para que as próximas usuárias já visualizem a nova coloração da via (Verde, Amarelo ou Vermelho).
7. O sistema incrementa a pontuação de "Colaboradora" no perfil da usuária que enviou o feedback.

### Pós-condições

- O banco de dados geográfico está atualizado com a percepção real de segurança.
- O próximo cálculo de rota (UC-06) utilizará os dados atualizados para sugerir caminhos.

## Cenários de Validação

### CT-01 — Atualização de Score por Iluminação
**Dado** que uma rua tinha score 80 (Verde)  
**Quando** o sistema recebe 5 feedbacks seguidos com a tag "Luz Quebrada"  
**Então** o sistema deve atualizar o score para 40 e mudar a cor da via para "Amarelo" em tempo real.

### CT-02 — Tratamento de Feedback Noturno
**Dado** que uma avaliação positiva ("Rua Segura") é recebida às 23:50h  
**Quando** o sistema processa a atualização  
**Então** esse benefício de score deve ser aplicado apenas ao "Perfil Noturno" da via, mantendo o score diurno inalterado.

### CT-03 — Proteção contra dados maliciosos
**Dado** uma conta de usuária criada há menos de 5 minutos  
**Quando** ela envia avaliações negativas para 50 ruas simultaneamente  
**Então** o sistema deve sinalizar esses dados como suspeitos e não atualizar o banco de dados principal até uma revisão humana ou sistêmica.

### CT-04 — Validação de Tags de Infraestrutura
**Dado** que a usuária enviou a tag "Ponto Violeta Fechado"  
**Quando** o sistema processa o dado  
**Então** ele deve alterar temporariamente o status do estabelecimento no mapa para "Offline" e notificar o administrador do sistema.

### CT-05 — Propagação da Atualização
**Dado** que o banco de dados foi atualizado com sucesso  
**Quando** uma nova usuária solicita uma rota que passa por aquele local 1 minuto depois  
**Então** o sistema deve considerar o novo score para decidir se mantém ou desvia a nova usuária daquela via.
