# UC-14 — Simular Segurança de Rota em Horário Futuro

**Produto:** Luminar  
**Objetivo:** Permitir que a usuária antecipe cenários de risco, simulando como a segurança das vias se comportará em horários diferentes do atual, baseando-se no fechamento do comércio, iluminação e padrões históricos de movimento.

## Atores

- **Usuária**
- **Sistema (Algoritmo de Predição / Banco de Dados Geoespacial)**

## Regras de Negócio Aplicadas

### RN-01 — Dinâmica de Score Temporal
- O sistema deve aplicar modificadores de peso negativos aos segmentos de via conforme o horário de fechamento dos estabelecimentos (ex: ruas comerciais perdem 0.4 de score após as 18:00h).

### RN-02 — Ciclo de Iluminação Automatizado
- O algoritmo deve cruzar as coordenadas do trajeto com a API de clima/astronomia para identificar o horário exato do pôr do sol na data simulada, ativando o "Modo Noturno" nos pesos de iluminação.

### RN-03 — Limite de Projeção
- A simulação deve ser permitida para qualquer janela de tempo nas próximas 24 horas, garantindo que os dados de eventos sazonais ou clima sejam minimamente precisos.

### RN-04 — Identificação de "Zonas de Sombra" Preditivas
- Se uma via possui alto índice de incidentes reportados em um horário específico (ex: saída de baladas ou pontos de ônibus deserto às 23:00h), o sistema deve sinalizar essa via como "Risco Preditivo", independentemente da infraestrutura física.

## Caso de Uso: UC-14

### Pré-condições

- O sistema possui acesso à base de dados de horários comerciais (Pontos Violetas e Google Places).
- A usuária inseriu um ponto de destino válido.

### Gatilho

- A usuária aciona o seletor de tempo ("Simular Horário") na tela de pré-visualização de rota.

### Fluxo Principal (Sucesso)

1. O sistema apresenta a rota padrão baseada no horário de "Agora".
2. A usuária desliza o seletor temporal para um horário futuro (ex: das 15:00h para as 22:00h).
3. O sistema reprocessa o grafo da malha viária, alterando a cor dos segmentos de acordo com os novos pesos preditivos.
4. O sistema identifica que a rua principal do trajeto original estará com o comércio fechado no horário simulado.
5. O sistema gera automaticamente uma **"Alternativa Preventiva"** que prioriza ruas que ainda possuam estabelecimentos 24h ou maior fluxo de pessoas naquela hora.
6. A interface exibe um resumo comparativo: "Às 22:00h, esta rua costuma ser deserta. Recomendamos o desvio pela Av. Principal (+5 min)".
7. A usuária visualiza as mudanças de "score" no mapa e decide salvar o plano ou ajustar seu horário de saída.

### Pós-condições

- A usuária obtém consciência situacional do trajeto antes mesmo de sair de casa.
- O sistema armazena a preferência de simulação para melhorar futuras sugestões de planejamento.

## Cenários de Validação

### CT-01 — Simulação de Saída de Faculdade
**Dado** que a usuária sai da aula às 22:30h  
**Quando** ela simula a rota para esse horário no período da tarde  
**Então** o sistema deve destacar as vias com maior movimento de estudantes e pontos de ônibus iluminados, evitando atalhos residenciais.

### CT-02 — Diferenciação Dia de Semana vs. Final de Semana
**Dado** que a usuária simula uma rota para domingo às 20:00h  
**Quando** o sistema processa os dados  
**Então** ele deve considerar que o comércio que abre aos sábados estará fechado, reduzindo o score de segurança daquelas vias em comparação a um dia útil.

### CT-03 — Transição de Iluminação (Entardecer)
**Dado** que o pôr do sol ocorre às 18:15h  
**Quando** a usuária simula a rota para as 17:30h e depois para as 18:45h  
**Então** o sistema deve mostrar uma queda nítida no score de ruas com histórico de "iluminação precária" na segunda simulação.

### CT-04 — Alerta de Evento de Risco Conhecido
**Dado** que há um evento de grande porte reportado para uma área (ex: jogo de futebol/protesto)  
**Quando** a usuária simula passar por perto no horário do evento  
**Então** o sistema deve sinalizar a área com um alerta de "Aglomeração/Atenção" e sugerir desvio.

### CT-05 — Cancelamento da Simulação
**Dado** que a usuária visualizou a projeção futura  
**Quando** ela clica em "Voltar para o Agora"  
**Então** o mapa deve restaurar instantaneamente as cores e pesos baseados no GPS e condições em tempo real.
