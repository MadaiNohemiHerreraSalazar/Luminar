# UC-18 — Avaliar Sensação de Segurança Pós-Trajeto

**Produto:** Luminar  
**Objetivo:** Coletar a percepção real da usuária sobre as condições de segurança e infraestrutura de uma rota recém-concluída, utilizando esses dados para atualizar dinamicamente o score das vias no banco de dados geoespacial.

## Atores

- **Usuária**
- **Sistema (API Luminar / Banco de Dados PostGIS)**

## Regras de Negócio Aplicadas

### RN-01 — Gatilho de Proximidade e Tempo
- O sistema deve disparar a tela de avaliação quando o GPS detectar que a usuária está num raio de 20 metros do destino final **OU** se a navegação for encerrada manualmente após pelo menos 50% do trajeto percorrido.

### RN-02 — Escala de Percepção (Likert Adaptada)
- A avaliação principal deve ser baseada numa escala visual de 1 a 5, onde:
    - **1:** Muito Insegura (Risco Crítico).
    - **5:** Muito Segura (Trajeto Ideal).

### RN-03 — Tags de Contexto Obrigatórias para Extremos
- Se a usuária avaliar com nota 1, 2 ou 5, o sistema deve exigir a seleção de pelo menos uma "Tag de Justificativa" (ex: "Sem iluminação", "Comércio aberto", "Presença de grupos intimidadores") para garantir a qualidade do dado.

### RN-04 — Peso por Reputação (Índice de Colaboração)
- O impacto da avaliação no banco de dados será ponderado pelo nível de colaboração da usuária. Usuárias que colaboram frequentemente com dados validados têm um peso maior (fator de confiança) no recálculo do score da via.

### RN-05 — Janela de Relevância Temporal
- Relatos de percepção de segurança expiram ou perdem peso após 4 semanas, garantindo que o mapa reflita as condições atuais da cidade e não dados obsoletos.

---

## Caso de Uso: UC-18

### Pré-condições

- A usuária concluiu um trajeto de navegação ativa.
- O dispositivo possui conexão com a internet (ou armazenará em cache via RN-Offline).

### Gatilho

- O sistema detecta a chegada ao destino e apresenta a tela: **"Você chegou! Como foi sua caminhada?"**.

### Fluxo Principal (Sucesso)

1. O sistema apresenta a interface de avaliação rápida com 5 ícones representativos de sensação de segurança.
2. A usuária seleciona o nível de segurança percebido.
3. O sistema expande uma seção de **"Tags Rápidas"** baseadas nas características do trajeto percorrido (ex: se passou por um Ponto Violeta, pergunta se ele estava realmente aberto).
4. A usuária seleciona as tags pertinentes (ex: "Iluminação Excelente", "Movimentada").
5. O sistema oferece um campo opcional para comentários em texto (observações específicas).
6. A usuária clica em **"Finalizar e Contribuir"**.
7. O sistema processa o "Índice de Solidariedade" daquelas vias, enviando as coordenadas e os pesos para o servidor.
8. O sistema exibe uma mensagem de confirmação e o impacto da ação: "Sua avaliação atualizou a segurança de 4 ruas para outras mulheres!".

### Pós-condições

- Os metadatos das ruas percorridas são atualizados no banco de dados.
- O Smart Routing (UC-07) passará a considerar esses novos dados para os próximos cálculos de rota naquela área.

## Cenários de Validação

### CT-01 — Avaliação de Rota Altamente Segura
**Dado** que a usuária percorreu uma avenida principal bem iluminada  
**Quando** ela avalia com 5 estrelas e a tag "Muito Movimentada"  
**Então** o sistema deve elevar o score de segurança dessa via para o próximo período de 24h.

### CT-02 — Identificação de Falha de Infraestrutura
**Dado** que a rota sugerida era "Verde" (Segura), mas a usuária encontrou lâmpadas apagadas  
**Quando** ela avalia com 2 estrelas e a tag "Luz da rua quebrada"  
**Então** o sistema deve rebaixar o status da via para "Amarelo" e emitir um log interno para o dashboard de análise urbana.

### CT-03 — Encerramento Prematuro da Avaliação
**Dado** que a tela de feedback aparece  
**Quando** a usuária fecha o app ou clica em "Pular"  
**Então** o sistema deve encerrar a sessão sem alterar os dados do banco, garantindo que apenas dados voluntários e completos sejam computados.

### CT-04 — Sincronização em Cache (Modo Offline)
**Dado** que a usuária chega ao destino em uma garagem sem sinal de rede  
**Quando** ela realiza a avaliação e envia  
**Então** o sistema deve salvar o JSON localmente e realizar o *upload* assim que detectar conexão estável.

### CT-05 — Detecção de Contradição (Segurança de Dados)
**Dado** que uma via tem histórico de nota 5 por 50 usuárias diferentes  
**Quando** uma única usuária avalia com nota 1 sem selecionar tags justificadoras  
**Então** o sistema deve registrar o voto, mas aplicar um peso reduzido para evitar flutuações maliciosas ou errôneas no índice.
