# UC-01 — Visualizar Índice de Segurança Dinâmico (Mapa Base)

**Produto:** Luminar

**Objetivo:** Renderizar no mapa a classificação de segurança de cada segmento de via em tempo real, utilizando cores para orientar a tomada de decisão da usuária antes e durante o deslocamento.

## Atores

* **Usuária:** Visualiza os dados e navega pela interface gráfica.
* **Sistema:** API do Luminar e Engine de Processamento Geográfico (Mapbox) que gerenciam a requisição e a renderização.
* **Banco de Dados (PostGIS):** Repositório com inteligência espacial que armazena os vetores das vias e calcula as geometrias.

## Regras de Negócio Aplicadas

### RN-01 — Composição do Score Dinâmico

* O índice de segurança de uma rua é calculated através de uma média ponderada ($S$), variando de 0 a 5:
* **Peso 40% (Infraestrutura):** Iluminação pública reportada e presença ativa de Pontos Violeta.
* **Peso 40% (Relatos Recentes):** Dados do UC-09 e RF-05 (Relato Rápido) enviados nos últimos 7 dias.
* **Peso 20% (Fator Temporal):** Ajuste automático com base no horário (vias comerciais perdem pontuação após o fechamento das lojas).



### RN-02 — Legenda Semafórica de Risco

* A visualização dos segmentos de via (polilinhas) na tela deve seguir estritamente o padrão:
* **Verde ($S \geq 4$):** Via recomendada, alta iluminação e comércio/movimento ativo.
* **Amarelo ($2.5 \leq S < 4$):** Via de atenção, iluminação parcial ou escassez de dados/poucos relatos.
* **Vermelho ($S < 2.5$):** Via de risco crítico, histórico de incidentes recentes ou breu total.



### RN-03 — Recálculo por Bounding Box

* Para garantir a performance e otimizar o hardware do dispositivo, o sistema deve processar e renderizar o score dinâmico apenas para os segmentos de vias contidos no quadrante geográfico (*Bounding Box* / área de zoom) visível na tela no momento atual.

## Caso de Uso: UC-01

### Pré-condições

* O mapa base (Mapbox) está carregado corretamente (RF-01).
* A usuária possui conexão de dados ativa para baixar os tiles de segurança e as informações de rede.

### Gatilho

* A usuária abre o aplicativo, movimenta a tela do mapa ou aplica um filtro específico de "Estado da Rua" (RF-04).

### Fluxo Principal (Sucesso)

1. O sistema identifica as coordenadas geográficas da área visível (*Bounding Box*) no smartphone da usuária (RN-03).
2. O sistema solicita ao servidor o Índice de Segurança para aqueles segmentos de rua específicos.
3. O servidor processa a fórmula do Score Dinâmico (RN-01), cruzando os relatos recentes do PostGIS com dados de infraestrutura e o fator temporal.
4. O sistema retorna os dados e sobrepõe ao mapa base do Mapbox uma camada de polilinhas coloridas (Verde, Amarelo ou Vermelho) sobre as ruas (RN-02).
5. O sistema exibe ícones flutuantes em trechos específicos onde o score sofreu queda brusca (ex: ícone de lâmpada apagada ou alerta de risco).
6. A usuária visualiza as opções de caminho na tela e identifica com facilidade as "Zonas Verdes" para planejar seu deslocamento.

### Pós-condições

* O mapa exibe a realidade atualizada da segurança urbana de Cascavel.
* O Smart Routing (RF-02) utiliza estes mesmos dados consolidados para traçar as rotas inteligentes.

## Cenários de Validação 

### CT-01 — Atualização por Relato em Tempo Real (RF-05)

**Dado** que uma rua está sendo exibida como "Verde" (Segura) no mapa

**Quando** uma usuária próxima envia um "Relato Rápido" de "Assédio" ou "Grupos Suspeitos"

**Então** o sistema deve reprocessar o peso de 40% e rebaixar o índice da via para "Vermelho" imediatamente para todas as outras usuárias na região.

### CT-02 — Transição Dia/Noite (Mapa Preditivo - RF-11)

**Dado** que a usuária utiliza o simulador de horário futuro para as 23:00h

**Quando** o sistema processa vias que são puramente comerciais (cujo comércio fecha às 18:00h)

**Então** a cor da via deve transitar de "Verde" para "Amarelo" ou "Vermelho", aplicando o redutor de 20% do fator temporal pela falta de movimentação ("olhos na rua").

### CT-03 — Sobreposição de Filtros (RF-04)

**Dado** que o mapa está exibindo o índice geral semafórico

**Quando** a usuária ativa o filtro específico de "Iluminação"

**Então** o sistema deve isolar a camada e destacar em amarelo/vermelho apenas os segmentos onde o critério de iluminação precária é o principal causador da queda de score.

### CT-04 — Tratamento de Dados Obsoletos (Limpeza de Histórico)

**Dado** que uma via teve um relato negativo de incidente há 31 dias

**Quando** o sistema calcula o score dinâmico hoje

**Então** esse relato antigo não deve mais influenciar na cor da via (saindo da janela de relevância de 7 dias), fazendo com que a rua retorne ao seu estado base de infraestrutura.
